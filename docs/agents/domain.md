# Domain docs

## Layout and reading rules

This repo uses a single-context layout:
- GLOSSARY.md at the repo root
- docs/adr/ for architecture decisions

Before exploring, read the glossary and ADRs relevant to the task.

If these files are absent, proceed silently. The domain-modeling
skill creates them when terms or decisions are resolved.

## Vocabulary

Use glossary terms consistently in issues, proposals, hypotheses,
and tests. If a needed concept is missing, reconsider the term or
note the gap for domain-modeling.

## Decisions

Explicitly flag proposals that contradict an existing ADR.
Name the ADR and explain why the decision should be reconsidered.
